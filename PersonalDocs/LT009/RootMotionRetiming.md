# 方法参考：根运动节奏修改

从 m001、m002 提炼（2026-10-14），作为同类修改的默认方法，避免每次重新讨论。两者的成果物已过时，文中引用的数值只作历史参考。工具链操作（导入、脚本、导出、验证细节）见 [Context.md](Context.md)。

## 0. 术语

LT009 文档与对话统一按下表理解；用到表外的说法时，先对应到表内术语。

**根与身体**

| 术语 | 定义 |
|---|---|
| 根骨 | `root_M`。在 Blender 中是 Armature **对象** `Root_M`，不是 pose 骨骼 |
| 前进轴 | 角色前进方向的世界轴；本组素材为 Blender 世界 `-Y` |
| 根曲线 | 根骨沿前进轴的时间—位移曲线 `s(t)` |
| 幅度 | 根曲线的总前进量 `s(T) - s(0)` |
| 节奏 | 根曲线去掉幅度后的形状：归一化进度 `p = (s(t)-s(0)) / 幅度` 随归一化时间 `t/T` 的变化 |
| 一级分支 | 根骨下的顶层骨骼 `Bip001`（全身）与 `ik_root`（IK 辅助） |
| 重心 | 骨盆、躯干、头、双臂、双腿加权得到的整体重心，不是单根 spine |
| 身体跟随 | 重心随根骨同节奏前进；用重心相对根骨的净漂移衡量 |

**脚**

| 术语 | 定义 |
|---|---|
| 着地 | 脚掌接触地面（高度阈值按素材定） |
| 落脚 | 一只脚由腾空变为着地的事件；对应的帧叫落脚帧 |
| 承重脚 | 即“重心支撑脚”：着地且正在承担身体重量、支撑身体前进的那只脚。不要求全程有承重脚，双脚可以同时离地 |
| 非承重脚 | 另一只脚；可以腾空（摆动），也可以着地 |
| 脚印 | 某次落脚在世界中的规划落点（前进轴位置 + 横向位置），编号同相位序列 |
| 静止窗口 | 承重脚在脚印上相对地面静止的连续时间段 |
| 滑步 | 着地的脚相对地面水平移动 |
| 前脚／后脚 | 某一时刻在前进轴上靠前／靠后的脚；按每段动画的入场相位判定，不固定为左或右 |
| 收脚 | 最后一次落脚：后脚向前迈到前脚附近站定，前脚不动 |

**步伐**

| 术语 | 定义 |
|---|---|
| 相位序列 | 按时间排列的落脚序列，如 `L0→R1→L1→R2→L2`。L／R 为左右脚，数字为该脚第几次落脚，0 表示开场时已着地 |
| 脚步相位 | 左右脚交替作为承重脚的时间结构：相位序列的顺序、步数和每次落脚帧 |
| 相位周期 | 双脚从某一前后位置出发，左右脚各踏地一次，回到下一个相同前后位置的过程。例：左前右后 → 右脚踏地成右前左后 → 左脚踏地回到左前右后，共两步 |
| 手臂摆动相位 | 左右手臂前后摆动在相位周期中所处的位置；应与脚步同周期 |
| 保持相位 | 相位序列的左右顺序、步数和落脚帧都与原动画相同（用户 2026-10-14 确认） |
| 步数 | 相位序列中的落脚次数，不含开场已着地的 `0` 号 |
| 步幅 | 相邻两个脚印在前进轴上的间距 |

**动画分段**

| 术语 | 定义 |
|---|---|
| 移动部分 | 根骨（重心）有大幅度位移的时间段。停步动画中即“停步部分”：从入场速度一路制动到基本停住 |
| 静止部分 | 角色站稳之后的动作：根骨只有微小位移（量级参考约 10 cm，按根骨量，不是硬阈值）；通常位于停步动画末尾 |
| 分界帧 | 移动部分与静止部分的交界帧：根曲线由陡**突然变平缓**的位置。没有统一的量化阈值，各动画、各项目不同；每段由 Claude 根据根曲线（及双脚最后站稳的时刻）给出候选帧，用户看过后确认，写入合同（用户 2026-10-14 确认） |

- 停步动画通常是“移动部分 + 静止部分”；有些动画只有移动部分，没有静止部分。
- 调整步幅只改移动部分；静止部分不修改，**世界位置也不变**。因此移动部分的终点必须接上原静止部分的起点。

**流程**

| 术语 | 定义 |
|---|---|
| 模式 A／B | 见第 2 节：A 只改根，B 根与身体一起改 |
| 合同 | 开工前与用户确定的参数表（第 3 节），写进子任务文档 |
| 阶段 | 模式 B 流程中需用户确认的步骤：一 根曲线、二 脚印、三 身体跟随与腿部解算 |
| 回读 | 把导出的 FBX 重新导入隔离场景，与导出前已验证的 Blender 结果逐帧对照（模式 A 下它与原动画世界姿态相同） |

## 1. 这类需求是什么

| 项 | 内容 |
|---|---|
| 改什么 | 根曲线的节奏，必要时连同幅度 |
| 必须保持 | 原动画风格、保持相位、手臂摆动相位与脚步一致、人形姿态合理 |
| 不允许 | 腿被拉长、关节异常扭曲、承重脚在静止窗口内滑步、增加步数凑步幅 |
| 允许 | 非承重脚贴地滑行（滑步）；双脚同时离地 |
| 修改范围 | 只改移动部分；静止部分（若有）原样保留，世界位置不变 |
| 典型素材 | UE 导出的起步／停步 Animation Sequence FBX，60 FPS，单 Armature + 单 Mesh |

## 2. 先选模式

两种模式的区别只有一个问题：**角色看起来的动作要不要变？**

```
          用户要的是“节奏/观感”变化吗？
                 │
        ┌────────┴────────┐
        否                 是
        │                 │
  模式 A：只改根        模式 B：根与身体一起改
  身体世界运动不变        身体跟随根，重排脚印、解腿
  （m001）              （m002）
```

| | 模式 A：只改根 | 模式 B：根与身体一起改 |
|---|---|---|
| 场景 | 根曲线有停顿／回退等数据问题，画面本身没问题 | 停得太急、冲过头回拉、步幅不对等观感问题 |
| 改动 | 根骨 + 一级分支的 9 条平移曲线 | 根曲线、`Bip001` 身体跟随、双腿与 IK 脚骨 |
| 脚 | 世界位置不变，天然不滑 | 按脚印重排并解腿 |
| 风险 | 低；误差可严格量化到 0.01 mm | 高；需要逐阶段让用户看 |

## 3. 开工前定合同

以下参数每次开工前写进子任务文档。“默认”列标“已确认”的是用户 2026-10-14 定下的规则；其余是归纳值，用户没指定时提给用户确认。

| 参数 | m001 取值 | m002 取值 | 默认 |
|---|---|---|---|
| 时长 | 不变 | 不变 | 不变，帧率与帧范围不动 |
| 分段 | 未区分 | 未区分 | 先判定有无静止部分及分界帧；静止部分原样保留、世界位置不变（已确认） |
| 首末根位置 | 不变 | 幅度重定（约 24 cm） | 模式 A 不变；模式 B 由用户给出。有静止部分时，移动部分终点 = 原静止部分起点 |
| 单调性 | 严格单调、正速度（用户在 m001 的特定要求） | 非递减 | 停步动画末段根骨停住，用非递减（已确认） |
| 速度下限 | Stop 10 cm/s，Start 1 cm/s | 无 | 只在模式 A 用；Start 类先看起步加速再定 |
| 参考动画 | 无 | 只取节奏，不取幅度 | 参考只提供节奏，不复制幅度和姿势 |
| 可改骨骼 | 根骨与一级分支 | 腿、骨盆、身体跟随；上肢尽量不动 | 腿、骨盆、身体跟随；上肢保留原摆动，手臂摆动相位与脚步一致（已确认） |
| 脚步 | 不涉及 | 保持相位 | 保持相位，含落脚帧不变（已确认） |
| 承重脚 | 不涉及 | 全程锁定（旧合同，较严） | 每个脚印静止窗口约 0.1 s；非承重脚可贴地滑行；可双脚离地（已确认） |
| 收脚 | 不涉及 | 前脚固定落点，后脚向前收拢 | 前脚不后撤 |
| 交付命名 | `_RootMonotonic` 后缀 | 未定 | `<源主名>_m###.FBX`，重做覆盖同名（已确认） |

## 4. 流程与确认点

每个 ⏸ 处停下等用户确认，确认前不进入下一步。

| 步骤 | 做什么 | 模式 A | 模式 B |
|---|---|:-:|:-:|
| 0 准备 | 导入独立场景、备份、记哈希；采样根曲线、重心、每只脚的落脚／离地帧；判定移动／静止部分与分界帧；定合同和容差 | ✔ | ✔ |
| 1 根曲线 | 构造新的根曲线（见第 5 节）⏸ | ✔ | ✔ |
| 2 补偿或脚印 | A：一级分支反向补偿；B：规划脚印，即定步幅 ⏸ | ✔ | ✔ |
| 3 身体与腿 | 身体跟随根骨，再按关节点解腿 ⏸ | — | ✔ |
| 4 导出验证 | 按 AnimEditQuality 出检查报告；保留式导出 FBX，回读，核对哈希（模式 B 尚未实际导出过） | ✔ | ✔ |
| 5 UE 验收 | 需用户授权 | ✔ | ✔ |

- 落脚帧以对原动画逐帧采样得到的接触区间为准，并记录接触判定阈值；不用文字记录里的约值（m002 曾把“左 63”误记成“左 53”）。
- 模式 B 阶段一做完脚一定会滑，属正常；这一步只看身体前进的节奏。
- 任何一步不可达（例如腿够不着脚印），**回退前面的步骤调幅度**，不在后面叠局部补丁。
- 一系列同类动画可以复用流程和算法，但每段单独确认骨架、时间范围、根曲线、相位序列和参数，不照搬上一段的左右脚与帧号。

## 5. 根曲线怎么构造

| 方法 | 用于 | 做法 |
|---|---|---|
| 单调回归 | 模式 A：贴合原曲线 | 投影到首末方向，`u(t)=s(t)-v_floor*t`，对 u 做固定端点、有界、等权最小二乘单调回归，再还原 |
| 归一化重映射 | 模式 B：换节奏 | 取参考动画的节奏，映射到目标时长，再乘目标幅度 |

- 只改前进轴（m002 是 `root_M` 的 `location[1]` 一条曲线）；横向、Z、旋转、缩放不动。
- “严格单调”即用户说的“斜率不能为 0 或 90 度”：速度严格为正且有限；不要求原本静止的轴也动。
- 模式 A 拟合的是原根曲线本身，不把根骨改成跟随骨盆。
- 单调回归前先检查可行：`D > v_floor * T`；幅度很小时高下限会挤掉拟合自由度。
- 约束冲突时报告用户，不静默改端点、时长或下限来掩盖。
- 投影到首末连线会改侧向偏离，需量化并请用户给允许范围（m001 为 1 mm、10 mm）。
- float32 存储会让实测速度略低于下限：拟合时留余量，不放宽验收阈值。
- “速度大于零”不等于“明显推进”：要检查低速区间的时长、占比和累计推进量。

## 6. 身体跟随与腿部（模式 B）

**脚印规划（定步幅）**

- 从原动画提取相位序列（m002 为 `L0→R1→L1→R2→L2`），保持相位。
- 只重设移动部分的脚印前进轴位置，横向沿用原动画；落脚帧不变；静止部分的脚印不动。
- 脚印先做成独立标记，不驱动骨骼。
- 收脚时前脚固定落点，后脚向前收拢。

**身体跟随**

- 根曲线冻结。以重心判断身体是否跟上，不只看单根 spine。
- 跟随补偿加在 `Bip001`，沿用根曲线的节奏。
- 骨盆可以下沉来迁就腿长，但有上限并保留原起伏（见 AnimEditQuality M6）；不全程压低。

**腿部解算**

- IK 只负责让承重脚落在脚印上，不能反过来主导全身节奏。
- 用实际髋—膝—踝关节点做解析两骨 IK，不用 FBX 骨尾端。
- 承重脚只需在静止窗口内锁定；非承重脚可以贴地滑行，不必额外锁定。
- 同步 `ik_foot_l/r` 到实际脚骨。

**上肢**

- 手臂摆动相位必须与脚步一致。落脚帧保持不变，所以手臂摆动一般保留原曲线即可。
- 若身体跟随或腿部调整后手脚明显对不上，只调摆动的时间，不改摆动姿势和幅度。

## 7. 姿态合理性检查

统一按 [AnimEditQuality.md](AnimEditQuality.md) 判定：合同、骨骼与关节、承重脚、运动感四类可程序化检查，及冲突时的优先级。

## 8. 反面教训

| 做法 | 结果 |
|---|---|
| 在上一版问题上继续打补丁（m002 v002–v005） | 局部指标变好，整体动作不可信；全部作废，从方法设计重来 |
| 增加落脚来锁脚（v003，12 步 vs 原约 4 步） | 步数暴增，破坏原相位 |
| 全程压低髋部 8 cm、强设首个承重脚（v004） | 锁脚通过，但重心和躯干姿势不自然 |
| 速度下限只设 1 cm/s（m001 第一版） | 不停但长时间几乎不动，观感仍是停顿 |

导入、导出、验证层面的坑（标准导出误差、`pose.bones` 误判等）见 [Context.md](Context.md)。
